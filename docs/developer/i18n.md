# Internationalization (i18n) Architecture

NH Reader features a **100% drop-in JSON-driven internationalization system**. Adding a new language or updating existing strings requires editing only a single JSON file without touching TypeScript, Rust, or build configuration.

---

## Directory Organization

All localization files reside in `src/lib/i18n/`:

```
src/lib/i18n/
├── index.ts        # LocaleCatalog loader, formatting helpers, and store wiring
├── en.json         # Canonical base locale (292 keys)
├── ar.json         # Arabic
├── de.json         # German
├── es.json         # Spanish
├── fr.json         # French
├── id.json         # Indonesian
├── it.json         # Italian
├── ja.json         # Japanese
├── ko.json         # Korean
├── nl.json         # Dutch
├── pl.json         # Polish
├── pt.json         # Portuguese
├── ru.json         # Russian
├── th.json         # Thai
├── tr.json         # Turkish
├── vi.json         # Vietnamese
├── zh-CN.json      # Simplified Chinese
└── zh-TW.json      # Traditional Chinese
```

---

## File Format & Schema

Each locale file must be valid JSON matching the exact nested key structure of `en.json`:

```json
{
  "_meta": {
    "code": "es",
    "name": "Spanish",
    "nativeName": "Español"
  },
  "app": {
    "name": "NH Desktop",
    "setup": "NH Desktop Setup",
    "version": "Version"
  },
  "nav": {
    "browse": "Navegar",
    "favorites": "Favoritos",
    "history": "Historial",
    "downloads": "Descargas",
    "blacklist": "Lista negra",
    "settings": "Ajustes"
  },
  "browse": {
    "title": "Navegar por el catálogo",
    "sortNewest": "Más reciente",
    "sortPopular": "Popular (Todo el tiempo)",
    "sortPopularWeek": "Popular esta semana",
    "sortPopularToday": "Popular hoy",
    "randomDoujin": "Doujin al azar"
  },
  "common": {
    "back": "Atrás",
    "loading": "Cargando…"
  }
}
```

## Mechanical Parity Verification Tool

The project includes an automated parity checker script (`scripts/check-i18n.mjs`):

```bash
npm run check:i18n
```

### Validation Checks
1. **JSON Syntax Validity**: Confirms all files parse cleanly without syntax errors.
2. **Key Parity**: Ensures every key present in `en.json` is present in every community locale file.
3. **Extra Keys Check**: Detects stale or orphaned keys not present in `en.json`.
4. **Empty Strings**: Flags untranslated empty strings.
5. **Exit Code**: Returns exit code `0` on 100% parity; returns non-zero if any locale fails validation (enforced in CI).

## Frontend Integration (`$t`)

Translations are accessed in Svelte 5 components via the reactive `$t` store:

```svelte
<script lang="ts">
  import { t } from '$lib/stores/locale.svelte';
</script>

<h1>{t('browse.title')}</h1>
<button>{t('browse.randomDoujin')}</button>
```

If a translation key is missing in the user's active locale, the `LocaleCatalog` automatically falls back to the English string.
